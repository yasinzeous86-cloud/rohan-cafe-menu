# منوی دیجیتال کافه — راهنمای نصب و انتشار

**نسخه ۱٫۰ — بسته‌ی آماده‌ی انتشار برای هاست‌های cPanel و DirectAdmin**

سیستم مدیریت منوی کافه: یک منوی آنلاین راست‌چین با پنل مدیریت، دیتابیس SQLite، قابلیت نصب به‌صورت PWA (کار بدون اینترنت بعد از اولین بازدید)، خروجی فایل آفلاین `.html` و ساخت کیوآر لینک. بدون Composer، بدون Node، بدون MySQL — فقط فایل‌ها را آپلود کنید.

---

## ۱. پیش‌نیازها

| مورد | الزام |
| --- | --- |
| هاست | Apache با دسترسی File Manager (cPanel یا DirectAdmin) |
| PHP | نسخه ۷٫۴ یا بالاتر |
| پسوند PHP | `pdo_sqlite` / `sqlite3` (پیش‌فرض تقریباً همه‌ی هاست‌ها فعال است) |
| دیتابیس | SQLite — نیازی به MySQL و ساخت دیتابیس نیست |
| ابزار ساخت | هیچ — بدون Composer، بدون npm، بدون مرحله‌ی Build |
| اینترنت روی گوشی مشتری | فقط برای اولین بازدید؛ پس از آن PWA با استایل محلی `assets/style.min.css` و فونت‌های لوکال کاملاً بدون اینترنت کار می‌کند (۱۰۰٪ خودکفا، بدون CDN) |

> نسخه‌ی آفلاین داخل کیوآر و منوی PWA کاملاً خودکفا هستند و برای کارکرد هیچ وابستگی خارجی ندارند.

## ۳. نصب گام‌به‌گام در cPanel

1. وارد **cPanel** شوید و **File Manager** را باز کنید.
2. به پوشه‌ی ریشه‌ی سایت بروید: `public_html` (برای ساب‌دامنه، مسیر مربوط به آن).
3. در **Settings** گزینه‌ی **Show Hidden Files** را روشن کنید تا فایل `.htaccess` آپلودشده دیده شود.
4. دکمه‌ی **Upload** را بزنید، همه‌ی فایل‌های بسته (شامل `.htaccess`) و پوشه‌ی `assets` را انتخاب کنید و آپلود کنید. اگر بسته را به‌صورت ZIP گرفته‌اید، می‌توانید ZIP را آپلود و با راست‌کلیک → **Extract** باز کنید.
5. مطمئن شوید ساختار نهایی دقیقاً مطابق بخش ۲ است (فایل‌ها در ریشه، تصاویر و اسکریپت‌ها داخل `assets/`).
6. دسترسی‌ها را تنظیم کنید — بخش ۵ را بخوانید.
7. آدرس سایت را در مرورگر باز کنید: `https://yourdomain.com/` → منوی کافه باید بالا بیاید.
8. پنل مدیریت: `https://yourdomain.com/admin.html` — بخش ۶ و ۷ را بخوانید.

**نسخه‌ی PHP:** در cPanel به **Select PHP Version** بروید و مطمئن شوید نسخه‌ی ۷٫۴ به بالا و پسوند `pdo_sqlite` فعال است.

---

## ۴. نصب گام‌به‌گام در DirectAdmin

1. وارد DirectAdmin شوید و **File Manager** را باز کنید.
2. به `public_html` بروید.
3. بسته‌ی ZIP را آپلود و با **Extract** باز کنید (یا فایل‌ها را تک‌تک آپلود کنید).
4. فایل‌های مخفی را نمایش دهید تا `.htaccess` را ببینید.
5. دسترسی‌ها را مطابق بخش ۵ تنظیم کنید.
6. نسخه‌ی PHP را بررسی کنید: **Extra Features → Select PHP version** (نسخه ۷٫۴ یا ۸.x و پسوند SQLite فعال).
7. آدرس سایت و سپس `/admin.html` را باز کنید.

> در هر دو پنل، اگر `.htaccess` اعمال نشد، مطمئن شوید `AllowOverride` فعال است (پیش‌فرض Apache روی هاست‌های استاندارد روشن است).

## ۵. دسترسی نوشتن برای `menu.sqlite` (مهم‌ترین بخش)

دیتابیس باید توسط PHP قابل **خواندن و نوشتن** باشد؛ در غیر این صورت پنل مدیریت خطا می‌دهد یا تغییرات ذخیره نمی‌شود.

| مورد | دسترسی پیشنهادی | توضیح |
| --- | --- | --- |
| پوشه‌ی اصلی و `assets/` | `755` | دسترسی خواندن و اجرا |
| پوشه‌ی `uploads/` | `755` | پوشه‌ی ذخیره‌سازی تصاویر آپلودشده (قابل نوشتن توسط PHP) |
| `menu.sqlite` | `644` | اگر خطای نوشتن داد → `666` |
| `.htaccess` | `644` | فقط خواندنی کافی است |
| بقیه‌ی فایل‌ها (`html`، `php`، `js`) | `644` | نیازی به اجرایی بودن نیست |

**نحوه‌ی تغییر در File Manager:** راست‌کلیک روی فایل → **Change Permissions** → عدد را روی مقدار جدول تنظیم کنید.

**نکته‌ها:**

- SQLite برای نوشتن، فایل‌های کناری `menu.sqlite-wal` و `menu.sqlite-shm` می‌سازد؛ به همین دلیل **پوشه** هم باید قابل نوشتن باشد، نه فقط فایل.
- اگر فایل‌ها را با FTP/SFTP آپلود کرده‌اید، مالک فایل باید کاربر هاست (همان اکانت cPanel) باشد. در File Manager با گزینه‌ی **Change Ownership** (اگر در دسترس بود) مالک را روی اکانت هاست بگذارید.
- **بازنشانی کامل:** اگر خواستید منو را به حالت اولیه برگردانید، فایل `menu.sqlite` را پاک کنید؛ در اولین درخواست، سیستم دیتابیس را از صفر می‌سازد و داده‌های نمونه را دوباره وارد می‌کند.

## ۶. توکن ادمین (پیش‌فرض و نحوه‌ی تغییر)

کل نوشتن‌ها در API با یک توکن انجام می‌شود.

- **مقدار پیش‌فرض:** `change-me-to-a-long-random-string`
- **محل تنظیم:** داخل فایل `api.php`، ثابت `ADMIN_TOKEN` (خط ۳۷ فایل):

```php
const ADMIN_TOKEN = 'change-me-to-a-long-random-string';
```

**⚠️ حتماً قبل از انتشار عوضش کنید.** هر کسی این توکن را داشته باشد می‌تواند منو را ویرایش کند.

**نحوه‌ی تغییر:**

1. در File Manager راست‌کلیک روی `api.php` → **Edit** (کدگذاری UTF-8).
2. رشته‌ی داخل `''` را با یک رشته‌ی تصادفی بلند جایگزین کنید (مثلاً از یک مولد رمز استفاده کنید، ۳۲ کاراکتر یا بیشتر).
3. فایل را Save کنید. فاصله یا نویسه‌ی خاص اضافه نکنید.

**نحوه‌ی استفاده در پنل:** پنل مدیریت هنگام ورود، توکن را از شما می‌پرسد و آن را در `localStorage` همان مرورگر ذخیره می‌کند (`menu_admin_token`). دکمه‌ی **Lock dashboard** توکن را پاک می‌کند و در ورود بعدی دوباره باید وارد شود. اگر توکن را عوض کردید، در مرورگرهای دیگر هم باید توکن تازه را وارد کنید.

> توکن هدر `X-Admin-Token` را می‌فرستد، نه پارامتر URL — چون آدرس‌ها در لاگ سرور ثبت می‌شوند.

## ۷. پنل مدیریت — بخش‌ها و امکانات

آدرس: `/admin.html`

| بخش | کارهایی که می‌شود کرد |
| --- | --- |
| **آیتم‌های منو** | افزودن/ویرایش/حذف محصول: نام، توضیح، قیمت، دسته، وضعیت (موجود / تمام شد / مخفی) و **بارگذاری مستقیم تصویر** (انتخاب فایل JPG/PNG/WEBP تا ۲ مگابایت با پیش‌نمایش زنده یا درج URL اختیاری) |
| **دسته‌بندی‌ها** | افزودن/ویرایش/حذف و ترتیب دسته‌بندی‌ها |
| **قالب و تنظیمات منو** | نام کافه، شعار، متن فوتر، واحد پول، **پیشنهاد روز**، **رنگ اصلی** (`primary_color`)، **فونت منو** (`font_family`: وزیرمتن، لاله‌زار، دانا، یکان‌بخت)، **تصویر پس‌زمینه** (`custom_bg_url`)، **نظرات مشتری‌ها** (`reviews_enabled` برای روشن/خاموش کل بخش، `reviews_title` برای عنوان، و ویرایش تا ۸ نظر با ستاره، آیتم، نام و متن) و **باکس‌های پایین منو** (`highlights_enabled` و ویرایش تا ۸ باکس با برچسب، آیکون، تیتر، متن و رنگ پُر/تیره) |
| **کیوآر و منوی آفلاین** | **دریافت کیوآر کد دائمی منو** + محاسبه خودکار آدرس زنده + دانلود خروجی فوق‌العاده باکیفیت مخصوص چاپ (۱۰۲۴×۱۰۲۴ PNG) + کپی لینک + **دانلود منوی آفلاین (`.html`)** |

**درون‌ریزی سریع منوی ایرانی:** در بالای صفحه‌ی «آیتم‌های منو» دکمه‌ی **➕ درون‌ریزی آیتم‌های پرفروش کافه‌های ایران** هست. با یک کلیک، ۸ آیتم پرتقاضای کافه‌ای (اسپرسو، لاته، کاپوچینو، موکا، وی‌۶۰، کیک شکلاتی، چیزکیک، شیک نوتلا) در دسته‌بندی‌های مناسب درج می‌شوند. این عملیات **تکرارپذیر است** (موارد تکراری رد می‌شوند) و همه‌ی آیتم‌ها با وضعیت `hidden` ساخته می‌شوند تا صاحب کافه اول قیمت‌ها را ویرایش کند و بعد آن‌ها را `available` کند؛ تا آن زمان در منوی عمومی دیده نمی‌شوند.

هر تغییری که ذخیره کنید بلافاصله در منوی عمومی اعمال می‌شود؛ نیازی به هیچ دکمه‌ی انتشار نیست. تغییرات از طریق `api.php` در `menu.sqlite` نوشته می‌شود.

## ۸. کیوآر کد دائمی، حالت آفلاین (PWA) و خروجی فایلی

### کیوآر کد دائمی منو (Permanent Live QR Code)

در تب **کیوآر و منوی آفلاین**، کارت «دریافت کیوآر کد دائمی منو» تعبیه شده است:

- **بدون نیاز به چاپ مجدد:** این کیوآر کد مستقیماً به آدرس زنده و دائمی منوی کافه اشاره می‌کند. با تغییر قیمت‌ها، نام آیتم‌ها، اضافه شدن تخفیف یا دسته‌بندی جدید، منو فوراً تغییرات را نشان داده و **هیچ نیازی به تعویض یا چاپ مجدد برچسب‌ها و استندهای QR روی میزها نیست.**
- **کیفیت چاپ بالا (۱۰۲۴×۱۰۲۴ پیکسل):** دکمه‌ی «دانلود کیوآر برای چاپ» فایل خروجی PNG را با وضوح فوق‌العاده بالا و حاشیه‌ی سفید استاندارد (Quiet Zone) ایجاد می‌کند تا مناسب چاپ روی تخته، پلکسی، استند و کارت ویزیت باشد.
- **تراز خطای Level H (۳۰٪ پایداری):** کد با حداکثر ضریب پایداری تولید می‌شود تا حتی در صورت ایجاد لکه، خط‌وخش یا قراردادن لوگو در مرکز آن، توسط دوربین موبایل مشتریان خوانده شود.
- **محاسبه خودکار آدرس:** آدرس دامنه و مسیر پروژه به‌طور خودکار شناسایی می‌شود و در کادر مربوطه نمایش داده شده و با یک کلیک کپی می‌شود.

### منوی آفلاین روی گوشی (PWA)

- فایل‌های `sw.js` و `manifest.json` در ریشه‌ی سایت هستند و `index.html` آن‌ها را ثبت می‌کند.
- بعد از **اولین بازدید آنلاین**، پوسته‌ی منو، تصاویر و پاسخ JSON در حافظه‌ی مرورگر کش می‌شود؛ از آن به بعد منو **بدون اینترنت** هم بالا می‌آید.
- روی موبایل، گزینه‌ی **Add to Home Screen** با آیکون `assets/icon-*.png` فعال می‌شود و منو مثل یک اپ باز می‌شود.
- کش با نسخه‌ی `VERSION` داخل `sw.js` مدیریت می‌شود؛ اگر منو تغییرات زیادی کرد، عدد نسخه را عوض کنید تا همه‌ی کش‌ها نو شوند.

### دانلود منوی آفلاین (فایل `.html`)

دکمه‌ی **دانلود منوی آفلاین (.html)** یک فایل مستقل می‌سازد که:

- کل منو رندرشده را با همان رنگ‌بندی و پس‌زمینه دارد (تصویر پس‌زمینه به‌صورت base64 داخل فایل است)؛
- تصاویر محصولات را تا جایی که ممکن باشد به base64 تبدیل می‌کند؛
- خودِ JSON منو (تنظیمات، دسته‌ها، آیتم‌ها) را داخل تگ `<script type="application/json">` همراهش دارد؛
- بدون اینترنت روی هر دستگاهی باز می‌شود و با کابل/واتس‌اپ قابل انتقال است (`menu-offline.html`).

## ۹. امنیت

1. **توکن ادمین** را قبل از انتشار عوض کنید (بخش ۶).
2. **محافظت از پوشه `uploads/`:** داخل پوشه‌ی `uploads/` فایل `.htaccess` خودکار ساخته می‌شود که موتور PHP (`php_flag engine off`) و اجرای هرگونه فایل اسکریپتی (`Require all denied` روی php، sh، py، cgi و...) را به طور کامل متوقف می‌کند تا امنیت سرور تضمین شود.
3. **اعتبارسنجی آپلود:** سیستم در سمت بک‌اند اندازه فایل را به حداکثر ۲ مگابایت محدود کرده و نوع فایل را از طریق MIME و تابع داخلی `getimagesize()` صحت‌سنجی می‌کند (فقط JPG، PNG و WEBP پذیرفته می‌شوند).
4. **`.htaccess` اصلی:** همراه بسته، دسترسی مستقیم مرورگر به `menu.sqlite` (و فایل‌های `-wal`/`-shm`) را مسدود می‌کند. این فایل را حذف نکنید:

```apache
<FilesMatch "^menu\.sqlite">
    Require all denied
</FilesMatch>
```

5. **`admin.html`** خودش محافظ رمز ندارد؛ امنیت واقعی در سمت سرور (`api.php`) است — هر درخواستِ نوشتن بدون توکن معتبر با `401` رد می‌شود.
6. اگر منو و پنل روی دامنه‌ی جداگانه‌ای هستند، `CORS_ORIGIN` را در `api.php` روی دامنه‌ی مجاز تنظیم کنید؛ مقدار پیش‌فرض `''` یعنی فقط همان دامنه مجاز است.

## ۱۰. عیب‌یابی

| علامت | علت محتمل | راه‌حل |
| --- | --- | --- |
| منو پیام «منو بارگذاری نشد» می‌دهد | مسیر `api.php` اشتباه است یا PHP خاموش است | مطمئن شوید `api.php` کنار `index.html` است و نسخه PHP فعال است |
| پنل خطای `401` می‌دهد | توکن اشتباه | توکن واردشده باید دقیقاً با `ADMIN_TOKEN` داخل `api.php` یکی باشد |
| ذخیره در پنل خطا می‌دهد یا ۵۰۰ می‌گیرد | دسترسی نوشتن دیتابیس | دسترسی `menu.sqlite` را `666` و پوشه را `775` کنید (بخش ۵) |
| تغییرات ذخیره می‌شود ولی در منو دیده نمی‌شود | کش مرورگر | منو را با Ctrl+F5 رفرش کنید |
| استایل لود نمی‌شود | خطای لود assets | مطمئن شوید فایل `assets/style.min.css` آپلود شده و دسترسی ۶۴۴ دارد |
| تغییرات در منو دیده نمی‌شود ولی پنل ذخیره کرده | کش سرویس‌ورکر مرورگر | در کنسول مرورگر از `caches.delete()` استفاده کنید یا `VERSION` داخل `sw.js` را عوض کنید و سپس رفرش بگیرید |
| منو با قطع اینترنت باز نمی‌شود | هنوز اولین بازدید آنلاین انجام نشده (یا SW ثبت نشده) | یک بار آنلاین باز کنید؛ بعد `sw.js` و `manifest.json` باید با کد ۲۰۰ جواب بدهند |
| تصویر محصول نمایش داده نمی‌شود | آدرس تصویر اشتباه است | `image_url` باید یک آدرس کامل `https://...` یا مسیر نسبی مثل `assets/...` باشد |
| کیوآر آفلاین با دوربین باز نمی‌شود | محدودیت دوربین گوشی | از حالت لینک استفاده کنید (بخش ۸) |
| `.htaccess` اعمال نشد | `AllowOverride` غیرفعال | از هاست بخواهید `AllowOverride All` را برای پوشه فعال کند |

## ۱۱. نکات فنی برای خریدار

- **بدون فرآیند بیلد:** HTML/CSS/JS خالص است؛ هیچ مرحله‌ی کامپایل یا نصب وابستگی توسط کاربر لازم نیست.
- **وابستگی‌های خارجی:** صفر (۱۰۰٪ خودمیزبان). تمامی استایل‌های Tailwind به‌صورت بهینه داخل `assets/style.min.css` کامپایل شده‌اند و تمامی فونت‌ها داخل `assets/fonts` همراه پروژه ارسال شده‌اند. هیچ درخواستی به سرورهای خارجی ارسال نمی‌شود.
- **تصاویر پیش‌فرض محصولات:** چند عکس نمونه از آدرس گوگل لود می‌شوند؛ با وارد کردن `image_url` برای هر محصول در پنل، تصویر دلخواه خودتان جایگزین می‌شود.
- **زبان و جهت:** منو و پنل مدیریت ۱۰۰٪ فارسی و راست‌چین (RTL) هستند.
- **پشتیبانی از موبایل:** منو از ابتدا موبایل‌فرست طراحی شده و در همه‌ی عرض‌ها واکنش‌گراست.
